# joshuafitzmorris.ca

Personal site for Joshua Fitz-Morris. One page, statically exported, no runtime.

## Stack

| | |
|---|---|
| Framework | Next.js 15 (App Router), React 19 |
| Language | TypeScript, strict |
| Styles | Tailwind CSS v4 (CSS-first `@theme`, no config file) |
| Type | Newsreader + Inter, self-hosted via `next/font` |
| Output | `output: "export"` — plain HTML/CSS/JS, deployable anywhere |
| Motion | CSS transitions driven by one small IntersectionObserver hook. No animation library. |

First-load JS is ~103 kB, and every animation is progressive enhancement: with
scripting off, `prefers-reduced-motion: reduce`, or no `IntersectionObserver`,
the page renders complete and still.

## Commands

```bash
pnpm install
```

```bash
pnpm dev
```

```bash
pnpm build
```

`pnpm build` writes the whole site to `out/`. To preview that build exactly as
it will be served:

```bash
npx serve out
```

Stop the dev server before building. Both use `.next/`, and a production build
run underneath a live `next dev` will clobber it and leave the dev server
throwing `routes-manifest.json` ENOENT until you `rm -rf .next` and restart.

## Editing content

Every word on the page lives in [`content/site.ts`](content/site.ts). Nothing
is hardcoded in the components, so adding a project or changing a metric is a
data edit, not a layout edit.

- `person` — name, contact, links, canonical URL
- `hero` / `contact` — the two display lines, split into parts so the italic
  gesture is explicit rather than parsed out of markup
- `metrics` — the proof row under the hero
- `work` — client projects (summary, prose, outcomes, stack)
- `building` — KitchenOS and Manifest
- `principles`, `stack`, `credentials`

The résumé PDF is served from `public/Joshua_FitzMorris_Resume.pdf`. It is a
copy of the master in `../linkedin-recruiter-assistant/resume/`, which is
generated by `build_resume.py`. **When the résumé is regenerated, copy it here
too**, or the download link goes stale:

```bash
cp ../linkedin-recruiter-assistant/resume/Joshua_FitzMorris_Resume.pdf public/
```

## The design language

The visual system is adapted from the KitchenOS design constitution
(`../Personal/kitchenos/DESIGN.md`) and holds to the same laws:

- **The field.** A gallery-white ground (`#FCFCFB` light, green-black
  `#0E1210` dark) with generous air.
- **Boxes must be earned.** Content sits bare on the field, separated by
  hairlines and space. There is not a single card on this page.
- **Chrome is ink.** Every control is warm black (or bone in dark mode) and
  never carries a hue.
- **One splash per band.** A blurred watercolor bloom bleeds in from
  off-canvas, anchored to the thing the band is about, breathing on a ~6.5s
  cycle. Never wallpaper, never floating free of content.
- **Type.** Serif semibold is the display voice, with the italic gesture on a
  single key word. Structure labels are small-caps eyebrows. Hierarchy comes
  from size and weight, never colour.
- **It breathes.** Blocks fade and rise as they enter the viewport, and go
  perfectly still under Reduce Motion.

Tokens live at the top of [`app/globals.css`](app/globals.css). Both themes
are checked against WCAG AA: every text colour clears 4.5:1 on its field.

## Social preview

[`app/opengraph-image.tsx`](app/opengraph-image.tsx) renders the 1200×630 link
card at build time, in the same field/ink/splash language as the page. Satori
cannot parse variable fonts, so `assets/` holds two static instances pinned
out of the Newsreader variable family (wght 600 roman, wght 500 italic, both
at optical size 36).

## Deploying

The build is a static directory, so any host works.

**Vercel** (zero config, detects Next.js):

```bash
npx vercel deploy --prod
```

**Cloudflare Pages / Netlify / S3 / GitHub Pages** — build command
`pnpm build`, publish directory `out`.

Not yet a git repository. To start one:

```bash
git init && git add -A && git commit -m "Initial site"
```
